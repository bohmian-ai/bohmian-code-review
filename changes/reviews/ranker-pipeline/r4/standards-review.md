### STANDARD-1 — Public evaluation library erases errors

**Classification:** VIOLATION. **Defect class and root cause:** the former executable live workflow became an exported library module while retaining `Box<dyn Error>` at its public boundary. The public API shape discards the error categories before consumers can match them. **Written rule:** `AGENTS.md:30` requires `thiserror` for library errors; `architecture/references/languages/rust-core.md:7` requires typed `thiserror` library errors. This was introduced when `crates/bohmian-code-review-eval/src/live.rs` entered the cumulative diff as a public module (`eval/src/lib.rs:15`).

**Owner and siblings:** `live::run` at `eval/src/live.rs:357-361`, with public `live` at `:340` and `print` at `:493`; their private workflow siblings are `Api::base_snapshot:118`, `Api::qualify:160`, `Api::trials:214`, and `Api::select:263`. `Api::select:267,312-313` and `live:341` also construct string errors, which the erased return type admits. Other added library errors in eval (`TrialError`, `SampleError`, `ArmsError`) and pipeline are typed; these are not siblings.

**Observable consequence:** a library caller cannot exhaustively match missing-token, malformed-repository, sampling, provider, and trial failures at the public API; it must downcast or inspect messages. **Testable correction:** use one `thiserror` error type for the live library workflow, with variants for its existing error categories and explicit token/repository failures, then propagate it through the three public functions and their private siblings. Keep the binary's display behavior. A caller-level test should match at least one typed failure without downcasting.
