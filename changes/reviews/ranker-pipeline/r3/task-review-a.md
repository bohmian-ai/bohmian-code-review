## Proposed finding

**TASK-A-1 — INCORRECT; history advancement keyed to tree instead of commit.** Defect class: a tree-only reuse decision bypasses a commit-scoped history update. The owner shape is `ColdBuild::build`'s reuse predicate, which treats equal tree identity as sufficient for the whole snapshot even though the snapshot also carries commit and merge history. In `Update::run`, the same-tree branch goes straight to this owner without reading the prior history. Sibling locations are `update.rs:93-95` (the facade route), `snapshot.rs:706-716` (the root reuse decision and successful result), and `pull_request.rs:222-229` (the later consumer of stale snapshot history). `ReviewPipeline::refresh` reaches `Update::run`; `ReviewPipeline::context` reads the stale pointer when it already exists. Both `Update::run` and direct `ColdBuild::run` can reach `ColdBuild::build`.

**Violated obligation:** intent decision 7 says update extends persisted co-change history with PRs merged since the previous snapshot; it is always on in both passes. Consider a default branch at commit A with tree T, then two merged PRs, one changing a file and the next reverting it, so new commit B has the same tree T. `refresh` sees B but returns `Reused(A)` before calling `CoChangeHistory::read`; neither merged PR's changed paths enter the published history. A later review against B ranks with F using A's history, potentially omitting co-change-only candidates. This is reachable without malformed provider input. The existing same-tree test repeats the same commit and only checks blob read avoidance, so it does not cover this case.

**Required correction:** make the shared snapshot reuse decision require the same commit as well as the same tree. On equal tree but changed commit, the update path must extend history from the prior snapshot and publish a snapshot for B while reusing the already indexed facts, without forcing a full archive or weakening completeness checks. Apply the same rule to direct `ColdBuild` callers. A focused fake-provider test should pin A/T, then B/T after merged PRs, call `Update::run` or `ReviewPipeline::refresh`, and assert the new pointer names B and its history contains the newly merged PRs; `PrContext` should then rank with those entries. Repeating B/T should still reuse. Preserve no-publication on unproved history and existing tree-identity checks.
