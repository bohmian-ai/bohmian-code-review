## Proposed finding

### HIST-1 — cold-depth proof is used as incremental completeness proof

**Classification:** INCORRECT; R1 `FIND-ranker-pipeline-2` is `CLASS_INCOMPLETE`. **Defect class:** the shared history reader accepts an incremental page cap on the cold-build count even though the previous snapshot boundary has not been reached. The owner is `CoChangeHistory::read`; its completion rule, rather than a caller's shape, permits the loss.

**Reachable case:** an update has prior history ending at `prior.before`; ten closed-PR pages each yield one eligible newly merged PR, in descending update and merge order. Page ten still advertises page eleven, which contains another PR merged after `prior.before`; the prior boundary lies farther back. After processing the tenth eligible PR, `history.prs.len() == COLD_DEPTH` and `pages.len() == MAX_DISCOVERY_PAGES`. The reader's cap branch returns success with `joined=false`, then does not append `prior.prs`. The eleventh new PR and every prior entry disappear from the persisted history. These pages are valid under the provider's returned shape and bounds.

R1's phrase “required cold depth or prior boundary” means cold depth for a *cold* read and prior boundary for an *incremental* read. Its additional instruction to preserve prior only after a proved join does not authorize an update to silently become a cold read. Controlling `intent.md` decision 7 explicitly requires the update to extend prior history with PRs merged since that snapshot; the design says the same. This code instead publishes a successful update after discarding it. Both `Update::run`'s incremental path and its fallback build pass `Some(&prior.history)` to this reader. `ColdBuild::complete` embeds the result and `publish` advances the pointer; `PrContext::review_history` subsequently ranks from it. The public `ReviewPipeline::refresh` reaches `Update::run`.

**Sibling locations:** `update.rs:120-124` (fallback and incremental reads), `snapshot.rs:723-729,848-857` (accepted history becomes a published snapshot), `review.rs:147-155` (public refresh), and `pull_request.rs:448-463` (context consumes it). They share one root cause and need one correction in the reader.

**Observable consequence:** refresh can return `Published` with incomplete persisted co-change history, and later PR context may select and rank the wrong files. The passing unproved-bound tests use zero qualifying PRs and therefore cannot detect this case.

**Testable correction:** require an incremental read to prove the prior boundary or true exhaustion before accepting it; a page cap still advertising more pages must fail without publication until that proof exists. Keep the cold ten-PR completion rule, genuine empty history, full-page stability rechecks, mass-edit exclusion, and 1,000-entry retention. Exercise a fake-provider update with ten new qualifying PRs across the bounded pages, `has_next=true`, an unjoined prior, and an additional unseen merge on page eleven; assert error and unchanged pointer through both incremental and fallback publication paths. A proved join must still prepend new entries to prior history.
