# Review-helper setup and symbolic context

Approved explicitly by the maintainer on 2026-09-25.
Authority: [implementation plan](implementation-plan.md), repository [design](../../../architecture/bohmian-code-review-design.md), [AGENTS.md](../../../AGENTS.md), and [agent rules](../../../architecture/agent-rules.md).

## Objective and user value

Create the independent `bohmian-ai/bohmian-code-review` Rust library workspace and its repository-native contributor workflow. A future code-review service must be able to supply Git-provider blobs in memory and receive useful, bounded symbolic context without cloning a repository or depending on unfinished codegraph-rs. The first usable outcome is a complete public-API journey implementing CodePal's two-pass symbol-to-file picker: parse supplied files, inspect changed code, rank related files, and return context within a token budget.

The workspace also needs Wyrd-structured, bohmian-code-review-specific agent skills, architecture authority, and scoped mise verification so an agent with no prior conversation can implement and review changes safely.

## Requirements and observable behavior

- **REQ-001 — Independent modular workspace.** The repository has a Rust 2024 workspace with Rust 1.94 as its minimum and initially pinned toolchain, a checked-in `Cargo.lock`, and six independently testable crates: `bohmian-code-review-core`, `bohmian-code-review-extract`, `bohmian-code-review-index`, `bohmian-code-review-resolve`, `bohmian-code-review-select`, and the public `bohmian-code-review` facade. Dependencies follow the documented downward direction. The repository includes its own manifests, toolchain file, `.gitignore`, `README.md`, `LICENSE`, and applicable third-party notices. It builds without a path, Git, or published dependency on codegraph-rs or Wyrd.
- **REQ-002 — Complete in-memory extraction.** Port all existing `codegraph-extract` logic and supported language routes from `codegraph-rs-parity`: native tree-sitter walkers, composite formats, routing, preprocessing, decoding, diagnostics, bounded synchronous batch parser, pinned grammars, and the extraction-relevant core values (`diagnostic`, `edge`, `language`, `node`, `position`, `reference`, `relative_path`, and their path byte limit). Given a validated relative path and bytes, extraction returns the donor's nodes, edges, references, positions, and file-local outcomes without a checkout. Preserve checked-in fixtures, goldens, vendored grammar sources, provenance, and third-party license obligations needed to verify the port independently; the accepted vendored grammar size does not justify reducing language coverage. Exclude donor storage, snapshots, local `SourceTree`, query facade, full reference resolver, search ranking, and unrelated identity/configuration code.
- **REQ-003 — Symbol-to-file index.** Given extracted facts one file at a time, build an in-memory index for exact, case-sensitive simple and qualified symbol names. Lookup returns every matching symbol's canonical path, kind, language, source span, and ID in deterministic path/location/ID order. Replacing a file atomically replaces its postings; removal is idempotent. An extraction failure leaves that file's previously complete state intact and does not affect another file. Source bytes are discarded after extraction; only facts and size metadata remain.
- **REQ-004 — Candidate reference lookup.** Extracted `reference_name` values and extractor-provided candidate names can be looked up against index postings. Return all plausible hits, including ambiguous hits. This result is candidate context, not a claim of exact semantic definition resolution. An unknown name produces no candidate rather than a fabricated match.
- **REQ-005 — Changed-line file ranking.** For a supplied head-side changed file and nonempty, ascending, nonoverlapping one-based changed-line ranges, parse the full changed blob. Use declarations whose spans overlap those lines and references located on those lines as query names. Match exact names against the index, exclude the changed file from secondary candidates, score each remaining file by its count of **distinct** matching query names, and return only positive-score files. Sort by descending score, then ascending canonical path. Include matched names and symbol spans as selection reasons. Repeated calls to one name do not inflate a score.
- **REQ-006 — Bounded context packing.** Given ranked files, caller-supplied candidate blob bytes, `max_files`, `max_tokens`, and a caller-supplied `Fn(&str) -> usize` tokenizer, return changed hunks first and then relevant candidate symbol spans in rank order. Count distinct selected files, including the changed file, toward `max_files`; count selected text with the supplied tokenizer toward `max_tokens`. Return source text, path, one-based line range, score/reasons, token usage, and explicit omissions. Never silently cut a span. An unfittable changed hunk is a typed budget error; missing selected blob bytes are a typed input error. No source is fetched by the library.
- **REQ-007 — Public journey.** An external Rust test using only `bohmian-code-review`'s public API can index in-memory TypeScript files, inspect a changed handler, receive deterministic ranked candidates, and build context that fits an exact caller-reported token budget. The journey includes a budget failure and missing-candidate input case and uses no mock of extraction, indexing, candidate lookup, or selection.
- **REQ-008 — Repository authority and skills.** The repository has its own `AGENTS.md`, agent rules, architecture design, routed engineering references, canonical `.agents/skills/cr-{spec,plan,implement,task-review,change-review,complete}` skills with `SKILL.md` and `agents/openai.yaml`, a generated `.claude/skills` mirror, and a `--write`/`--check` sync script. Adapt applicable Wyrd Rust, testing, implementation, and spec-driven rules to this library; exclude Wyrd product, SQL, server, UI, PyO3, audit, `advise`, and `ui` rules or skills. Track this change under `changes/active/review-helper-setup/` through approved spec, bounded outcome-complete tasks, independent task review, integrated change review, and completion. Task boundaries cover extractor/bootstrap, index/resolver, selector/facade/journey, and repository gates without prescribing private code layout.
- **REQ-009 — Scoped verification.** `mise.toml` defines `fmt`, `fmt:check`, `lints`, `test:extract`, `test:index`, `test:resolve`, `test:select`, `test:symbolic-context:journey`, `test:rust`, `check:skills-sync`, `check:default`, and `gate`. Each component lane runs only its owner package; the journey lane runs the facade's external public test. `test:rust` aggregates component and journey tests, `check:default` runs formatting, Clippy, and workspace type-check, and `gate` runs `check:default`, `test:rust`, and skill-sync. CI invokes these same task names. An absent owner/test target fails rather than skipping. Every component is independently testable, while the public journey remains the primary acceptance proof.
- **REQ-010 — One-file-at-a-time indexing.** The facade accepts one caller-supplied blob per upsert and retains extracted facts and byte length after the call, not the input blob. A many-file input can be streamed through successive upserts without keeping all source bytes resident. No fixed memory or latency performance claim is made without reproducible measurements on a named environment.

## Constraints, invariants, scope, and non-goals

- **INV-001 — No-clone runtime boundary.** Runtime code in these crates neither clones/discovers a Git repository nor reads source from disk, makes network calls, persists an index, calls a model, or publishes review comments. Test fixture reads and build-time vendored grammar compilation are allowed. The future service verifies repository, commit, path, and blob identity before supplying bytes.
- **INV-002 — Honest coverage and resolution.** The index covers only caller-supplied files. It does not report complete repository coverage without evidence. Candidate hits remain ambiguous; no exact cross-file semantic target is inferred from a name match.
- **INV-003 — Source and budget safety.** The index does not retain source bytes. Returned context may own only selected text. Canonical paths and changed-line ranges are validated before indexing or ranking; selection never exceeds the explicit file or caller-counted token ceiling, silently truncates a span, or disguises a missing candidate as successful context.
- **INV-004 — Determinism.** Given identical facts, changed lines, candidate blobs, limits, and token counter, lookup, scores, ranking, reasons, omissions, and context order are identical. Repeated references to one name do not change a file's score.
- **INV-005 — Independent ownership.** Extraction semantics have one owner; postings, candidate matching, ranking/packing, and public composition each have one owner. No downward crate depends on the facade or a higher stage. Donor repositories are source/provenance input during porting, never runtime dependencies.
- **INV-006 — Test and artifact integrity.** Existing extractor expected outputs are not rewritten to make the port pass. Generated Claude skill mirrors are changed only through their canonical `.agents` sources and sync script. A failing gate is fixed or reported, not bypassed.

In scope are the six-crate library, full extractor port with pinned grammars and verification inputs, in-memory indexing and candidate matching, changed-line scoring and context packing, public journey, repo authority/skills, mise lanes, and CI. **Out of scope:** a Git provider adapter, cloning, repository discovery, durable index or source storage, exact definition resolution, base-side/deletion-only analysis, cross-repository search, shared context service, model review loop, comments, feedback, PostgreSQL, TypeScript SDK parity, tags, and crate publication. A deletion-only input receives an explicit unsupported-input error in this revision.

## Expensive-to-reverse decisions and interfaces

1. The public production boundary is the `bohmian-code-review` Rust crate. Its synchronous, stateful facade accepts caller-supplied paths and bytes and composes extraction, index, candidate resolution, and selection; it owns no hidden IO. Consumers can upsert a file and receive its symbols, references, and file-local diagnostics; remove a file; look up a symbol; rank a changed head-side file; and build bounded context from supplied candidate blobs.
2. Shared facts are extracted `Node`, `Edge`, `RawReference`, `Language`, diagnostics, positions, and canonical `RelativePath` values. The extractor owns grammar behavior and provenance. Downstream crates consume these facts rather than defining parallel representations.
3. The symbol index is ephemeral and in memory. It supports upsert, remove, and exact lookup, but makes no durability or completeness claim.
4. Candidate resolution is name-based and preserves ambiguity. The v1 score is a count of distinct exact matched names per other file, with canonical path tie-breaking; score cannot be replaced by fuzzy, embedding, or backend-specific ranking without a new approved revision.
5. Token counting is caller-supplied because model tokenizers differ. Changed source takes budget first; no selected span may exceed the caller's exact count. The returned value is structured for a service-owned shared context store, not a storage implementation.
6. The initial repository uses Wyrd's lifecycle *shape* under `cr-*` names, with repository-native authority. A spec becomes approved only through explicit maintainer approval; implementation, task review, and change review cannot self-approve it.

## Acceptance criteria and credible evidence

- **AC-001 — Independence.** A clean checkout of `bohmian-ai/bohmian-code-review` has the workspace, toolchain, lockfile, documentation, license, and notices required by REQ-001 and, once Rust dependencies are available, builds and tests without the donor checkouts, Node, credentials, PostgreSQL, Git source checkout, or network service. Manifests and runtime code show no donor path/Git dependency or forbidden IO capability.
- **AC-002 — Extraction closure.** Every copied extractor route compiles and the copied fixture/golden corpus runs locally without expected-value edits. Grammar pins, vendored sources, provenance, and applicable notices are present.
- **AC-003 — Index and candidate closure.** Focused tests prove simple/qualified lookup, duplicate declarations, unknown names, atomic file replacement, idempotent removal, unsupported/malformed-file outcomes and isolation, ambiguity, deterministic hit ordering, and repeated one-file-at-a-time upserts that retain facts and byte lengths rather than source blobs.
- **AC-004 — Scoring and budget closure.** Focused tests prove changed-line filtering, unique-name scoring, path ties, canonical validation, file/token ceilings, exact callback-based token counts, explicit omissions, unfittable changed hunks, missing candidate blobs, and deletion-only refusal.
- **AC-005 — Complete symbolic-context journey.** A public-API test indexes `src/handler.ts`, `src/user.ts`, `src/format.ts`, and `src/unrelated.ts` from byte slices. Changed handler lines reference `lookupUser`, `saveUser`, and `formatUser`; `src/user.ts` scores 2, `src/format.ts` scores 1, and unrelated is absent. A one-secondary-span budget selects the user span with correct text/range/reasons/tokens. A repeated run is identical. Budget and missing-blob negative cases fail explicitly. All production stage owners are exercised.
- **AC-006 — Governance and lanes.** Every `cr-*` skill validates, all relative links resolve, the Claude mirror matches canonical skills, and its sync script writes and detects drift. Every named mise lane in REQ-009 exists and fails on a missing target; the public journey is a distinct lane, and CI uses the same names. The exact integrated candidate passes formatting, lints, component tests, journey, and the full gate with a clean diff.

Credible evidence is source and manifest inspection, checked-in extraction fixture results, focused Rust tests against real crate APIs, the public in-memory journey, skill validation and mirror diff, mise/CI logs, and independent task/change reviews. A rewritten golden, direct internal fixture shortcut, mock stage, skipped test, or assumed complete repository index does not establish acceptance.
