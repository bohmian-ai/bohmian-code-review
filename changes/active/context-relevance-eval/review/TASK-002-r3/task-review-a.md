## Proposed finding

### TASK-A-1 — INCORRECT: an aliased Rust import is recorded under its source name

- **Root cause and defect class:** `bindings` treats the last segment of every extracted Rust `use` path as a local bound name. The public Rust extractor deliberately emits the original path for `use_as_clause` (`rustlang.rs:937–941`, `:951–957`), omitting the alias. The evaluator then creates a binding for the source name at `trial.rs:410–412`, though that name was not introduced into local scope. This is wrong import-binding identity at the shared binding owner. The private `Bindings` map can represent the required ambiguous or absent result; its shape does not force the defect.
- **Sibling sweep:** `Corpus::new` calls this owner for every indexed base file (`trial.rs:267`) and D downstream reads the result (`:777–786`); `Change::new` calls it for every remaining changed head (`:618–623`) and D upstream reads it (`:743–761`). Every Rust `use ... as alias` whose source leaf is also queried has this class. Python alias extraction emits the local alias, so it is not the same defect; unaliased Rust uses and R2's resolved-module rule remain valid.
- **Violated obligation:** Spec revision 4's D rule scopes *that reference* only when an explicit import binding identifies one indexed base module; unresolved or ambiguous bindings retain C lookup. TASK-002 Scenario 2 requires that behavior using public facts. An alias binds the alias, not the source leaf.
- **Reachable consequence:** With indexed `src/io.rs` and `src/alt.rs` both declaring `read_all`, a remaining changed `src/user.rs` containing `use crate::io::read_all as io_read_all; use crate::alt::read_all;` and a changed-line `read_all()` calls the `alt` import. The extractor emits import paths `crate::io::read_all` and `crate::alt::read_all`; `bindings` inserts both under `read_all`, marks them ambiguous, and D falls back to C, crediting both modules. If `alt.rs` is withheld, its rank/score and sent outcome can differ from the required D result, which should scope to `alt.rs`. With only the aliased import and a local `read_all`, the false binding instead scopes a name that should remain unscoped. Both routes run from `evaluate` through the same `bindings` owner and `score`.
- **Testable correction:** At the evaluator's Rust binding derivation, distinguish the local name used by an upstream changed-line call from the source path of an imported downstream dependency. Do not assign an aliased import's source leaf as its local binding; preserve that import's genuine downstream reference to its source module, unaliased Rust and Python behavior, and the R2 rule. A focused no-network `evaluate` trial with the aliased `io` import plus unaliased `alt` import should show D credits only `alt` for changed-line `read_all()`, while C credits both; exercise upstream and downstream consumers of the owner. If public facts cannot establish the local alias, the upstream path must retain C fallback instead of inventing one.

Prior `FIND-TASK-002-1` and `FIND-TASK-002-2` remain closed by `trial.rs:757–759` and the Python coordinate association at `:390–406`. `FIND-TASK-002-3` is closed by `trial.rs:743–755` and its focused regression. This proposal is a separate local-binding identity defect.
