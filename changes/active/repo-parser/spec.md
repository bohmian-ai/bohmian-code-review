# Repository parser and symbolic review-context library

Drafted 2026-09-25 from the [pipeline proposal](symbolic-context-service-plan.md). This revision defines only the reusable library and its injected dependency contracts. Its journeys and acceptance obligations remain in scope when implementation is divided into tasks. Revision 11 is approved.

## Objective and user value

Build a standalone Rust library that supplies review agents with relevant, bounded code context for a GitHub pull request without cloning or checking out a repository. Its independently callable facades build a reusable default-branch symbol snapshot, update that snapshot, overlay a PR head in private memory, rank related files, publish selected context once to injected shared storage, and read it back by context ID. The library defines narrow traits for storage and persistence so a consuming crate can inject its own implementations. A reviewer gets useful cross-file context quickly; a caller can see when coverage is partial.

This implements the “Building Code Context” portion of [Snap CodePal](https://eng.snap.com/codepal). It does not implement CodePal's model review loop, finding verifier, comments, feedback, or cross-repository search.

## Scope and ownership

**Pipeline library:** Add a library crate to this workspace. It owns GitHub and GHES source access, Git identity and blob verification, repository eligibility, bounded ingest, snapshot build/update, PR overlays, context publication and read-back. It exposes independently callable cold-build, incremental-update, PR-context, and context-read facades, plus the narrow dependency traits they need. It uses the public `bohmian-code-review` library without duplicating extraction, resolution, scoring or packing. It has no dependency on any consuming crate and starts no server or job loop.

**Library revision:** Extend the current six-crate, IO-free library only where the pipeline needs reusable source-independent facts, path eligibility, multi-file ranking, and candidate-only packing. Preserve the existing single-file public journey and crate ownership. The six library crates never gain Git, HTTP, database, object-store, model, or source-file IO; the new outer library crate owns its permitted Git and storage IO.

**Consumer boundary:** A consuming crate supplies verified tenant/installation/repository identity, GitHub credentials, trait implementations for storage and persistence, operation deadlines and cancellation. It may call the facades at different points in its own review pipeline. This change does not implement that consumer, webhook routes, job scheduling, review agents, models or comment publication. Downstream workflows receive a context ID and obtain the diff separately; they count the complete model request before submission.

**Non-goals:** exact/compiler-grade definition resolution, deletion-only semantic review, cross-repository search, GitLab, Git checkout or mirror, persistent PR-specific symbol snapshots, full source blobs or archives in durable storage, full-repository indexing when GitHub's recursive tree listing is truncated, and implementation of downstream review agents.

This specification is the change packet for the library revision and outer pipeline crate in this repository. The required integration tests, including the real-repository PR test, run from this repository through the public facades and injected test implementations. This repository's architecture and contributor rules must be updated to permit the outer library's Git and storage IO while keeping the six existing crates IO-free before implementation begins.

## Terms and required contracts

- **Eligible file:** A Git blob with mode `100644` or `100755` on a supported library path, initially at most 1 MiB, outside path segments `node_modules`, `vendor`, `third_party`, `dist`, `build`, and `.git`, and outside `.min.js`/`.min.css` outputs. Root `.gitattributes` generated/vendored overrides apply; nested attributes are not required in this revision. LFS pointers are skipped after content inspection. Symlinks and submodules are excluded. Eligibility and exclusions are reported by reason.
- **Symbol snapshot:** An immutable, versioned object for one caller-supplied tenant, installation, repository, extraction version, snapshot format version and Git tree. It contains eligible path/blob identities, file status, extraction facts and coverage, but no source text. A skipped eligible path retains its blob identity and reason. A mutable pointer identifies the current default-branch snapshot.
- **Complete snapshot:** Every eligible file in the listed tree was fetched, verified, and indexed. A parser failure, archive mismatch beyond fallback limits, or other unindexed eligible file makes an attempt incomplete; that attempt may supply honest scoped context for its current invocation but is not published as the reusable default-branch snapshot. Excluded and unsupported paths remain counted separately.
- **PR overlay:** A private, invocation-local transformation of a snapshot index to the PR head tree. A complete overlay applies every eligibility, blob, addition, removal, and mode difference. A failed changed blob removes stale facts; it never preserves symbols from an older blob under a new identity.
- **Coverage:** Context records repository versus scoped coverage, snapshot completeness, overlay completeness, eligible/indexed counts, and skip reasons independently. Only repository scope with both completeness flags true may claim full PR-head coverage. Candidate resolution remains name-based and ambiguous even under full coverage.
- **Review context:** The immutable shared object after ranking and budgeted packing. It contains selected candidate files' actual source text spans, verified repository/PR/head identity, paths and blob SHAs, one-based ranges, scores, matched names, token estimates, omissions, not-analyzed files, budget, and coverage. The diff remains separate.
- **Context ID:** An opaque identifier returned to the caller for downstream use. Tenant-scoped metadata binds it to one review-context object key and identity; the read facade requires matching tenant and installation, so possession of an ID alone is insufficient. The consumer authorizes its callers before invoking that facade.

## Requirements and externally observable behavior

### Library contract

- **REQ-001 — Persistable, source-free facts.** The public facade can export each indexed path's byte length and declaration facts and load those facts into a new in-memory index without parsing source. The persisted projection contains only fields needed to reproduce exact lookup, ranking reasons, and candidate spans; it excludes verbatim source fragments such as docstrings and signatures. Loading the same facts produces the same ranking and candidate context as a fresh parse. Invalid paths or malformed facts fail explicitly without corrupting other indexed files.
- **REQ-002 — Extraction identity and eligibility.** The library exposes an extraction version that changes when extracted facts or grammar behavior changes, and a path-only language/eligibility query for pre-download filtering. Ambiguous routes may still use content at parse time. Version changes cannot silently reuse incompatible snapshots.
- **REQ-003 — Multi-file selection.** Given multiple changed head-side blobs and validated nonempty added-line ranges, the facade unions overlapping declaration names and references on changed lines, excludes every changed path from secondary candidates, scores each remaining file once per distinct matched name, and sorts by descending score then canonical path. Candidate-only packing accepts this ranking without a single changed-head blob; it counts only selected candidate files and emits explicit omissions under caller-supplied file/token limits. Existing single-file ranking and changed-hunk packing remain compatible.

### Ingest and snapshot lifecycle

- **REQ-004 — Authenticated source inputs.** The GitHub source client supports github.com and configured GHES instances. Every facade receives caller-supplied tenant, verified installation and repository identity, and credentials through its invocation contract. It validates repository, commit/tree, path and blob identity before source enters the symbolic library. Invalid identity, unauthorized repository access, oversize input and unsupported PR state fail explicitly. Webhook verification and delivery deduplication are consumer responsibilities outside this change.
- **REQ-005 — Bounded cold build.** When the cold-build facade is called with no compatible pointer, it lists the default-branch tree, applies eligibility rules, streams a commit-pinned archive without writing source to disk, verifies each eligible entry against its Git blob identity and indexes files without retaining the full source set. Archive substitutions/omissions use bounded verified blob fallback. A truncated tree, unindexed eligible file or exhausted archive bound yields an incomplete result for scoped PR fallback. The call honors a caller-supplied deadline and cancellation; a caller may wait for it before starting an independent review clock.
- **REQ-006 — Immutable snapshot publication.** Snapshots are scoped by caller tenant, installation, repository, extraction version, format version and tree identity. A duplicate key is reused only after identity and content validation. Only complete attempts publish a reusable snapshot or advance the pointer after the object exists and is validated. Failed or incomplete attempts leave the prior pointer unchanged and return coverage plus retry reason; callers may retry the whole build. Creation time and branch commit identity live outside the tree-keyed payload. The library exposes collection of expired unreferenced snapshots and removal of a repository namespace; callers choose when to invoke it.
- **REQ-007 — Incremental default-branch updates.** The update facade reads the current default-branch tree, compares eligible path/blob identities with the prior snapshot, preserves unchanged facts, fetches changed blobs, and removes deleted or now-ineligible facts. It is independently callable after a push, default-branch edit or version change. The PR-context facade may report a stale default-branch pointer without waiting for an update; the caller can invoke the update facade separately. Only a complete update publishes a new snapshot and advances the pointer. Failed changed blobs remove stale facts from the attempt and leave the prior pointer unchanged; a whole-build retry is possible. A running review keeps its loaded immutable snapshot.
- **REQ-008 — Scoped fallback.** When a recursive tree is truncated, an archive is too large, or a full build fails, a review indexes only eligible files near its changed paths, within a fixed file and request bound. Nothing from this scoped index is published as a full snapshot. Context records scoped coverage, indexed counts, and omissions. A scoped result is useful context, not a claim of repository-wide absence of matches.

### PR selection and output

- **REQ-009 — Head-correct PR context.** Every review loads a compatible immutable snapshot into a private index and reconciles it against the PR's pinned head tree, including default-branch changes after the PR base. The context records one base SHA and head SHA. If the overlay bound is reached or a blob fails, the output records incomplete overlay coverage while still analyzing valid PR files. Different PRs never expose their unmerged facts to one another. Candidate source is fetched at its verified blob identity only after ranking. A changed path is never selected again as secondary context.
- **REQ-010 — Diff and budget behavior.** The PR-context facade reads the PR's base/head SHAs before requesting paginated PR files, obtains every available page up to the provider's documented ceiling, then re-reads the PR. If either SHA changed, it discards those pages and retries within its bound; it never publishes context assembled across a detected PR change. Each file's head blob identity is checked against the pinned head tree before its patch is used. Available patches become validated head-side added lines. A missing/malformed patch, binary file, deletion-only change, unsupported language, or failed changed blob is listed as not analyzed; one such file does not erase valid work for other files. The review agent receives the diff separately, so the pipeline packs candidates only. It allocates a configured review token budget across estimated diff, prompt reserve, and selected context; zero remaining context yields an explicit budget reason. Estimates and omissions are reported. The estimate is never represented as a guarantee that the final model request fits; the downstream agent must count its complete request before submission.
- **REQ-011 — Shared context handoff.** The PR-context facade writes one immutable context object containing selected source spans and metadata. After the object is complete and validated, injected persistence publishes a context ID and exact object key. The caller passes that ID to authorized downstream workflows; the library's read facade returns the same spans without repeating ranking, packing or blob fetches. Missing/corrupt objects fail explicitly and never substitute current branch content. Missing snapshots, unsupported input and exhausted rate budget produce explicit retry, scoped fallback or terminal reasons.

### Operation, isolation, and limits

- **REQ-012 — Retry-safe facades.** Cold build, update, PR-context build, read and cleanup are independently callable and safe to retry after interruption between object write and metadata publication. They converge to a valid result or a visible terminal failure without holding a persistence transaction across GitHub or storage IO. The library exposes typed retry/terminal status and never equates partial progress with complete coverage. Job queues, scheduling and cross-installation claims are consumer responsibilities.
- **REQ-013 — Provider budget and resource bounds.** Pipeline GitHub calls honor installation-specific primary/secondary limits, retry-after/reset information, concurrency ceilings and bounded retry time. File size, archive expansion, fallback blobs, PR overlay, scoped files, PR-file count, memory and invocation duration are bounded. The cold-build, update and PR-context facades each honor an independent caller-supplied deadline; the library imposes no maximum, and a caller can begin the review deadline after cold readiness or scoped fallback. Cancellation and partial progress are reported honestly. No benchmark latency or memory claim is accepted without a named environment and reproducible measurements.
- **REQ-014 — Security and source lifetime.** Tenant, installation and repository identities scope snapshot/context keys and every read; no cross-tenant cache reveals another tenant's content. Credentials and source text never appear in logs, metrics, snapshots or persistence metadata. Only the selected context object contains source text at rest. It is readable for 24 hours from publication and never after `expires_at`; the library exposes deletion of expired objects, retries failures and reports lag when called. No full archive, checkout or raw blob cache is persisted. Source bytes remain only in bounded process memory during ingest, overlay, packing and authorized reads. Archive redirects and paths prevent credential forwarding, traversal, symlink extraction and unbounded decompression.
- **REQ-015 — Injected persistence.** The library defines two narrow traits because repository snapshots and PR contexts have separate lifecycles and may live in separate stores: a snapshot store for snapshot metadata/pointers, conditional publication and expired-snapshot cleanup, and a context store for context metadata, exact-key read lookup and expired-context cleanup. Each facade accepts only the stores it uses. Neither accepts a raw PostgreSQL pool or depends on a consuming crate. Each trait contract carries validated tenant, installation and repository identity, object-before-row visibility, and exact-key lookup. In-memory test implementations prove retry and isolation semantics. A consumer that implements the trait with PostgreSQL is responsible for tenant-bound connections, forced RLS and separate privileged operator operations; no concrete SQL adapter or migration is required in this change.
- **REQ-016 — Injected storage.** The library defines a narrow trait for immutable objects, exact-key reads and deletion. A consuming crate implements it with its own storage handle (Wyrd over `wyrd-storage`, which already supports local filesystem, GCS, AWS S3 and Azure Blob Storage); the library has no dependency on that crate and ships no storage backend or OpenDAL adapter. Snapshot and context objects may use separate trait instances. No downstream workflow receives direct storage credentials.
- **REQ-017 — Library integration and verification.** Tests in this repository exercise every facade and their composed journey against injected storage/persistence implementations and fake GitHub. A controlled real-GitHub contract run and the configurable S20 run are explicitly invoked outside normal CI. No consumer server, PostgreSQL migration, webhook route, worker or downstream agent is implemented as part of this change.
- **REQ-018 — Independently callable facades.** Any consuming crate can invoke cold snapshot build, incremental update, PR-context build and context read independently, passing verified tenant/installation/repository identity and implementations of the storage/persistence traits. Each returns typed coverage, identity and retry/terminal status where relevant. None requires an all-in-one review method or imports a consumer type. Retrying a stage never exposes a partial snapshot or context as complete.

## Invariants and material decisions

- **INV-001 — No clone and single stage ownership.** The outer pipeline library obtains Git data through provider APIs and processes transient bytes in memory. The existing six crates retain their no-IO boundary and dependency direction. The outer crate does not reimplement symbol matching, scoring, or packing, and it does not own a server or worker loop.
- **INV-002 — Honest coverage.** Missing facts, skipped files, truncated trees, and incomplete overlays remain distinguishable in persisted context. An absent candidate under partial coverage is not evidence that no matching file exists.
- **INV-003 — Version and blob integrity.** A fact belongs to its verified path/blob identity and extraction/format version. Old facts cannot survive a failed replacement under a new blob identity. A pointer targets only a validated, complete snapshot; an incomplete attempt does not replace it.
- **INV-004 — Isolation and determinism.** Snapshots are immutable and scoped per caller tenant/installation/repository; PR overlays are private. The same complete facts, changes, candidate bytes, and limits yield the same ranking and selected spans. Name ambiguity is preserved.
- **INV-005 — Bounded source persistence.** No full source archive, checkout, or raw blob cache is persisted. Selected span text is persisted only in the tenant's shared review-context object; tenant metadata rows contain identifiers, `expires_at`, and object keys, not source text. Authorization rejects reads at or after `expires_at`, even if deletion is still being retried.
- **INV-006 — No hidden budget success.** Missing source, malformed diff, an unfittable budget, or rate exhaustion is reported. Estimated service tokens are not mislabeled as a model-exact count.
- **INV-007 — Injected dependency isolation.** Library methods require tenant and installation identity at every durable seam and do not accept unscoped object keys or raw SQL pools. The test persistence implementation fails closed on a missing identity and rejects cross-tenant or cross-installation reads. Concrete PostgreSQL RLS and privileged operator behavior belong to whichever consumer supplies that implementation.

The following decisions are fixed because changing them affects public or persisted contracts: an outer library crate here with independently callable facades; narrow library-defined object-storage, snapshot-store and context-store traits; no dependency on a consuming crate; GitHub App identity and GHES compatibility; source-free immutable snapshots with injected pointers; caller tenant identity separate from GitHub installation ID; versioned snapshot keys; private PR-head overlays; explicit multi-axis coverage; candidate-only context because the diff is separate; one shared source-bearing context object with lookup by context ID; a 24-hour read cutoff; and deterministic name-based ranking through the symbolic library. Concrete host scheduling, webhook routes, SQL schema, migrations and downstream agents are outside this change.

The initial operational ceilings from the proposal are 4 GiB uncompressed archive bytes, 200 archive-fallback blobs, 2,000 changed blobs before an update rebuilds from an archive, 300 PR-overlay changes before reporting incomplete overlay coverage, 300 scoped files, the provider's 3,000 PR-file response limit, 15 selected candidate files, a 64,000-token review allocation, and a 4,096-token prompt reserve. These are configurable limits, not evidence that the service performs well at those sizes. Execution deadlines are caller-supplied per facade; the proposal's 15-minute cold build, 10-minute update and 30-minute review are host policy, not library limits. A task may tune a non-review ceiling with measured evidence, but may not remove the bound or silently relabel incomplete work as complete.

## Acceptance criteria and evidence

- **AC-001 — Library journey.** The public, credential-free two-pass journey extends to fact export/load equivalence, two-file PR ranking, exclusion of all changed files, distinct-name scoring, and candidate-only packing. Existing single-file behavior remains green. `mise run gate` passes for the library revision. Evidence: real public APIs, owner tests, journey result, format/lint output.
- **AC-002 — Cold and warm flow.** S1–S2 show a verified cold snapshot, unchanged-object reuse, no tarball on warm review, correctly ranked/packed context, and explicit call accounting. A paused-clock scenario proves that first-review waiting does not consume its 30-minute execution allowance, while a timed-out cold build yields scoped coverage without changing that allowance. Evidence: fake GitHub plus storage integration and recorded calls.
- **AC-003 — Update and isolation.** S3–S9 and S16–S17 show incremental updates, burst convergence, stale-pointer detection after a missed update call, version changes, concurrent/stale-base PR isolation, force-push handling, and crash-safe pointer publication. An incomplete build/update leaves the prior pointer unchanged; a later whole-build attempt can publish a complete snapshot for the same tree/version. Complete snapshot-plus-overlay facts and ranking equal an independent from-scratch parse of the same pinned head. Evidence: integration assertions and oracle comparisons.
- **AC-004 — Honest degradation.** S10–S11 and S18–S19 show bounded scoped indexing, archive/LFS handling, incomplete snapshot/overlay flags, malformed/absent patches, large PR pagination, and explicit budget outcomes. A failed changed blob removes old facts and remains identified as skipped. Evidence: service scenarios, file-local negative tests, coverage assertions.
- **AC-005 — Security and identity isolation.** S12–S15 show provider rate outcomes, invalid caller identity rejection, tenant/installation isolation, and source text confined to protected selected-context objects. Authorized reads return the same context before expiry; reads at or after 24 hours, by another tenant or installation, fail. Contract tests with two identities prove cross-tenant reads/writes fail in the injected test persistence, absent identity fails closed, and deletion failures are retried/reported. No PostgreSQL schema or RLS test is required of this library. Evidence: paused-clock, injected-adapter, object and log inspection.
- **AC-006 — Provider compatibility.** A credentialed, opt-in contract run against a controlled real GitHub repository validates archive redirect/shape, recursive tree and blob responses, PR patch omission, and conditional/rate-limit behavior before rollout. GHES endpoint/rate-header variation has a tested local contract. Evidence: captured contract results; tests never need production credentials in the normal CI lane.
- **AC-007 — Capacity evidence.** Reproducible fixed-commit measurements cover approximately 1k, 10k and 50k eligible-file repositories: archive bytes, cold time, memory peak, snapshot size, warm p50/p95 and API calls. Provisional targets are confirmed or revised from measurements before rollout. Evidence: benchmark record and resource-bound results; no hosted shadow run is required for this library change.
- **AC-008 — Full lifecycle review.** `$cr-plan` derives bounded tasks only after approval; each task gets implementation and independent review, and an integrated immutable change review checks all requirements, journeys, cross-task seams, and exact diff. Evidence: active packet, task verdicts, full service verification, and final review.
- **AC-009 — Injected infrastructure.** The library runs snapshot write/read, context publish/read, missing-object failure, identity isolation and cleanup through caller-supplied trait implementations. Snapshot and context stores are exercised as separate implementations. Evidence: trait contract tests against in-memory implementations in this repository.
- **AC-010 — Stage facade journey.** Tests call each public facade separately, then compose cold build, update, PR-context build and context read through the same injected capabilities. They prove the library starts no server or worker loop. Evidence: public library journey in this repository.
- **AC-011 — Live large-repository PR journey.** A dedicated, configurable test in this repository can be invoked with an existing PR number in the real `bohmian-ai/wyrd` GitHub repository (initial target [PR #91](https://github.com/bohmian-ai/wyrd/pull/91)). It uses the real GitHub API and this library's public facades with injected test storage/persistence to build context and read it by ID; it does not clone, mock GitHub, change the PR or require code in the target repository. It records PR URL/base/head, coverage/omissions, selected paths/spans, object/metadata identity, read-back, calls, time and memory. Missing credentials or inaccessible PR fail visibly; empty selected context cannot pass silently. It stays outside normal CI and `mise run gate`, but one passing recorded run is required before completion.

S1–S19 refer to the named fake-provider and injected-adapter scenarios in the [proposal's verification scenarios](symbolic-context-service-plan.md#8-verification-scenarios). S20 is the separately invoked real-repository PR scenario. All are required acceptance coverage of this library change; no consumer implementation is required.

## Open material decisions

No material library decision is left open. Revision 10 removed the previously assumed host implementation obligations. The 24-hour guarantee is a read cutoff; physical deletion is retried and reported after expiry rather than promised at the exact second.
