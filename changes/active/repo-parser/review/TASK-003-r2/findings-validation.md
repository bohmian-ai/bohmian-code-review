### FIND-TASK-003-2 — cancellation during archive consumption

**Root cause and siblings.** `Ingest::stream_entries` checks `execution.check()` inside `for entry in tar.entries()` (`snapshot.rs:696-703`). Advancing that iterator can read through the previous entry before the next check; `entry.read_to_end(&mut bytes)` at `snapshot.rs:726` reads a whole eligible file without checking. The stream is `GzDecoder` inside a byte-only `BoundedReader` (`snapshot.rs:667-680`, `github.rs:558-599`), so neither decompression nor compressed-body reads observe the cancellation flag. These are two read sites of the same defect class, not separate findings. `Ingest::fallback` and `ColdBuild::run` do check later (`snapshot.rs:740-775,518-533`), preventing publication but only after archive reading returns.

**Reachability and production consequence.** The public `ColdBuild::run` calls `GitHubClient::archive` then `consume_archive` (`snapshot.rs:509-525`). `GitHubClient::archive` supplies a streaming `Archive.reader` from `HttpResponse.body` (`github.rs:990-1023`); the production `UreqTransport` supplies `response.into_body().into_reader()` (`github.rs:131-168`). A caller can cancel while a large entry is being read or while tar advances across a large unselected entry. The build continues archive IO/decompression until an entry boundary or IO completion, despite cancellation. The byte ceilings limit total work but do not make the cancellation effective at the read boundary. The request timeout, capped by remaining deadline (`github.rs:1209-1215`), limits production network waiting for a deadline; it does not make cancellation promptly observable during a body read. Spec REQ-005 says the cold-build call honors cancellation and REQ-013 requires honest cancellation and bounded invocation duration (`spec.md:62,76`).

**Independent reproduction.** Source-path trace above is sufficient: `Read::read_to_end` repeatedly calls the input reader; no `Execution` reference exists in the reader chain or inside the call at `snapshot.rs:726`. A cancellation after the `snapshot.rs:699` check cannot be observed until `read_to_end` finishes. The existing focused test, `mise exec -- cargo test --locked -p bohmian-code-review-pipeline --lib snapshot::tests::interruption_during_a_complete_archive_never_publishes -- --exact`, passed one test in 1.01s, but its hook cancels before the archive response is returned (`snapshot.rs:1756-1762,1782-1789`); it cannot exercise mid-entry cancellation.

**Why the prior correction is incomplete.** R1 FIND-2 added an `Execution` parameter to `consume_archive`/`stream_entries` and entry-level checks. That shape leaves the byte reader independent of `Execution`, so archive reads can continue after cancellation. The earlier correction must be reopened under the same ID. Its final pre-publication check remains valid and must stay.

**Smallest safe correction.** Reuse `Execution::check` at the archive stream's shared read boundary in `Ingest`, preserving the existing compressed and expanded byte ceilings, Git blob verification, fallback classification, typed `Interrupted` outcome, and final pre-publication check. A cancelled read should stop further archive reads and carry the interruption into `fallback`, which already marks remaining pending files `NotFetched`. Do not add a transport, provider API, worker, timer abstraction, or dependency. This only changes the candidate-owned ingest path. The transport's in-progress blocking read may still wait for its configured timeout; the correction prevents subsequent reads and parsing after it returns.

**Focused closure proof.** Drive the public cold build with a streaming test body that cancels after its first chunk within a tar entry, and a separate archive whose iterator must skip a large unselected entry. Assert no later body chunks are read, outcome is `Incomplete(Interrupted(Cancelled))`, coverage marks remaining eligible files `NotFetched`, storage receives no new object, and the prior pointer stays. An already-expired `Execution` at the ingest owner checks the deadline path without waiting for real time. Keep the existing complete-archive cancellation test for the pre-entry boundary.

### FIND-TASK-003-6 — wall-clock sleep in deadline test

**Root cause, rule, and consequence.** `snapshot.rs:1791-1799` gives the `interruption_during_a_complete_archive_never_publishes` test a deadline one second away, then its transport hook loops over `Instant::now()` and calls `std::thread::sleep(Duration::from_millis(5))` until expiry. The added test directly violates the written prohibition on “adding sleeps instead of deterministic synchronization” at `architecture/references/languages/implementation-execution.md:224-229`. It consumes about one second in the narrow test and makes its trigger depend on wall time. The corresponding cancellation half uses a direct `CancelToken` and is deterministic (`snapshot.rs:1782-1789`). No other newly added test sleep appears in the base-to-candidate diff (`git diff ... -- snapshot.rs`, search for added `sleep`).

**Independent reproduction.** The focused test command above passed, taking 1.01s; that result does not excuse the rule violation. The cited `snapshot.rs:1797` is the actual sleep, and the rule applies to tests changed by this remediation diff.

**Smallest safe correction.** Remove the wait loop. Exercise expiration directly with an already-expired `Execution` at the ingest owner and keep the cancellation hook for the public archive path. That preserves both interruption variants without a fake clock, new helper, or dependency. If the test retains a public-facade deadline assertion, use an already-expired execution at a public boundary and state that it covers early rejection, not expiry during a request. Closure is a focused run of the corrected test plus inspection that the newly added deadline test contains no sleep or wall-clock polling.
