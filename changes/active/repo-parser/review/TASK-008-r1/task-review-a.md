## Proposed finding

**TASK-A-1 — INCORRECT — error-contained declarations remain eligible for extraction.** Defect class: recovered-tree traversal accepts declaration nodes below an `ERROR` node. The owner's shape permits this: each walker receives and recursively traverses a raw tree-sitter `Node` without an error-excluding traversal boundary. The first wrong decision is in the walker traversal, before facts reach the facade or snapshot. It violates spec REQ-002 at `changes/active/repo-parser/spec.md:56` and the task's material stop condition.

**Exact owner and siblings.** Rust extraction passes the parsed root to `Walker::visit_node` at `rustlang.rs:247`; its generic child descent at `rustlang.rs:601-605` enters `ERROR`, and `function_item` descendants are emitted at `rustlang.rs:562-564`. The same unrestricted generic child descent is present in the changed TypeScript/JavaScript walker at `tsjs/mod.rs:915-920`. The whole-file defer removal exposes the same class across the other ported language entrypoints; closure must cover all newly recovered languages, not only the Rust reproducer. This review reproduced the violation in Rust and inspected the TypeScript traversal, but did not claim a second language-specific reproducer.

**Reproduction and consequence.** With pinned `tree-sitter-rust 0.24.2`, parse `fn before() {}\n{ fn inside() {}\nfn after() {}\n`. The tree is `(source_file (function_item before) (ERROR (function_item inside) (function_item after)))` in abbreviated form. The candidate's public `Extractor::extract` emits `before`, `inside`, and `after`. `inside` and `after` are inside the parser's `ERROR` region, so their names can enter exported snapshot facts and alter lookup/ranking despite REQ-002. I reproduced this using a temporary `/tmp` Cargo probe linked to the candidate extractor and pinned grammars; it left reviewed source unchanged.

**Required, testable correction.** Shape recovered traversal so declarations inside parser error regions cannot reach fact emission, while recovered sibling declarations remain available. Exercise an `ERROR` subtree that contains a syntactically recognizable declaration through the public extractor, and prove only declarations outside that subtree survive. Apply the same recovery boundary to each newly unblocked language path; avoid caller-side or per-emission guards.

Overall result: **FAIL**. The live run and green gate do not exercise the `ERROR`-wrapped declaration case. Verification limit: the live GitHub run was assessed from its recorded artifact, not repeated with credentials; language-specific `ERROR` subtrees other than Rust were not reproduced here.
