## TASK-B-1 — Verified PR blobs bypass the configured file-size ceiling

- **Classification:** INCORRECT. **Defect class/root cause:** File eligibility trusts the tree's optional reported size, but the PR paths do not check actual verified blob length against the facade's `max_file_bytes` after fetching. The owner shape is not the problem; the missing content check at PR admission is. The provider's independent `max_blob_bytes` is 1 MiB by default and does not enforce a lower caller-selected `PrContextLimits::max_file_bytes`.
- **Violated obligation:** The spec defines eligible files as at most the configured file bound, REQ-013 bounds file size and memory, and TASK-005 requires bounded PR head/scoped context. `PrContextLimits::max_file_bytes` is documented as the largest eligible file.
- **Reachable path and evidence:** `eligibility::exclusion` only excludes `entry.size` when it is `Some` and above the cap (`eligibility.rs:276–278`). A head-tree entry with `size: None` or an understated size therefore enters `Ingest`. `PrContext::changed_head` fetches its SHA-verified bytes and indexes them when pending, then returns them for ranking without comparing `bytes.len()` to `max_file_bytes` (`pull_request.rs:416–430`). With no snapshot and a valid changed patch, the public `PrContext::run` follows this path. Set the facade cap below the provider blob cap, supply a canonical supported changed file larger than that cap with missing size metadata and a matching Git SHA: it is analyzed and may count as indexed, contrary to the file ceiling.
- **Sibling sweep:** The same PR invocation's candidate fetch accepts and caches verified bytes without applying that cap (`pull_request.rs:465–476`), so a matching candidate with missing/understated tree size can be packed. A compatible snapshot built with a larger cap can also be reused when the current PR facade has a smaller cap: `Ingest::reuse` loads unchanged facts without checking their recorded byte length (`snapshot.rs:910–935`). Cold archive and fallback have their own actual-size checks; these are the PR-side gaps.
- **Observable consequence:** Caller-selected smaller file limits do not bound changed-head extraction or selected candidate source; scoped coverage can count an oversized changed file as indexed. Selected context can contain a file the current invocation's eligibility limit should exclude.
- **Testable correction:** Apply the current facade file-size bound to verified changed-head and candidate bytes and to reused snapshot facts before they enter PR ranking or packing. Keep mandatory changed-file verification and file-local diagnostics; report an oversized changed head as not analyzed and prevent it from entering the index. Preserve provider SHA checks, token budgeting, and the head-tree identity. Prove with a public PR-facade test using `max_file_bytes` below `GitHubClient::max_blob_bytes`, absent/understated tree sizes, an oversized changed head, an oversized matching candidate, and a warm snapshot built under a larger cap. Assert indexed count, selected spans, diagnostics and provider calls.
