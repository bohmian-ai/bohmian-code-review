## Finding

**STD-1 — FAIL, repository verification rule.** Defect class: capacity benchmark input is mutable rather than pinned. Root cause: the sole live capacity entrypoint calls `ColdBuild::run`, which obtains the current default-branch head, and the refreshed report accepts the resulting recorded-commit rows as the capacity proof. The entrypoint shape permits no fixed-commit run. Sibling locations: all three capacity rows in the task record and the corresponding wyrd, vscode, and rust reports share this route. This violates `architecture/bohmian-code-review-design.md:38` (no benchmark claim without reproducible measurements). `TASK-007:95` explicitly states the reproduction window is limited to the time the commit remains the default-branch head; `examples/live_pr.rs:98` and `snapshot.rs:636-638` show why. Once a branch advances, the documented command samples another commit, so an independent reader cannot reproduce the claimed cold, warm, memory, and call figures at the recorded tree. Correction: provide and record a repeatable fixed-commit benchmark route plus exact commands for all three repositories, or obtain an approved authority change to the reproducibility requirement. Keep S20's existing real-PR behavior and source-verification guarantees. Closure proof: rerun one recorded commit after its default branch advances or through a fixed-commit fixture, and show the report still names that commit; provide the three full commands and resulting identities.

Overall: **FAIL** (STD-1). No other material repository-rule violation found. The provider's live 403/429 and GHES paths remain a documented verification limit of the task evidence, not a separate standards finding.
