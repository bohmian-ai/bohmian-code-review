## Proposed findings

### TASK-A-1 — MISSING: benchmark entrypoint cannot rerun the recorded commits

- **Root cause / defect class:** The benchmark reuses `ColdBuild::run`, whose only source is the moving default branch. The benchmark entrypoint has no pinned-commit input. This is an evidence-runner shape problem, not a reason to alter the production cold-build contract.
- **Sibling locations:** `examples/live_pr.rs:98` is the only cold benchmark call; `src/snapshot.rs:621-637` is its pinning path. The three recorded repository rows at task `:91-93` all use it.
- **Obligation:** AC-007, REQ-013, and TASK-007 Approach 4 require reproducible fixed-commit capacity measurements.
- **Evidence / reproduction:** The task record `:95` explicitly says the rows are reproducible only while each commit remains default. `ColdBuild::run` pins `repository.default_branch` at execution time. Repeating the recorded command after a default-branch advance measures a different tree, so the fixed-commit latency, memory, calls and warm reuse cannot be reproduced.
- **Consequence:** The capacity numbers remain useful observations, but they do not satisfy the fixed-commit reproducibility criterion.
- **Testable correction:** Give the opt-in benchmark runner a way to pin its three recorded source commits without changing ordinary `ColdBuild::run`, rerun the measurements at those SHAs, and record exact commands plus matching commit/tree identities. Re-running the same command after the default branch advances must still target the same tree.

### TASK-A-2 — MISSING: controlled real-provider contract evidence

- **Root cause / defect class:** The task treats incidental observations from public-repository S20/benchmarks as the separate controlled provider contract. The evidence record contains no controlled-repository run or captured rate/conditional result.
- **Sibling locations:** `examples/live_pr.rs:86` constructs the client used by all four reports; task record `:85-86` makes the same contract claim for those runs. The local fake tests in `src/github.rs` cover the unobserved branches but do not create real-provider evidence.
- **Obligation:** REQ-017 and AC-006 require an opt-in, credentialed contract run against a controlled real GitHub repository, including archive, tree, blob, PR patch omission and applicable conditional/rate behavior.
- **Evidence / reproduction:** The four reports name `bohmian-ai/wyrd`, `microsoft/vscode` and `rust-lang/rust`. Task `:86` says no live 403/429 occurred and the client sends no conditional requests. There is no controlled test repository or raw contract report in `evidence/TASK-007/`.
- **Consequence:** The criterion's provider boundary is unverified even though local fake tests and incidental live runs give partial confidence.
- **Testable correction:** Run and preserve one explicitly controlled, read-only provider contract with exact command and captured results for the applicable real paths. Identify conditional behavior as inapplicable only if the approved contract permits that interpretation; otherwise route that conflict through a spec decision. Do not exhaust a production quota to manufacture a 403/429.
