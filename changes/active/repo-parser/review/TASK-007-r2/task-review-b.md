## Proposed finding

**TASK-B-1 — INCORRECT / `FIND-TASK-007-1` class incomplete.** Defect class: the benchmark pins only the cold snapshot commit, while the measured PR input remains a mutable PR number. The owner shape is the `live_pr` capacity entrypoint, which has `BCR_COMMIT` but no fixed or checked PR base/head for the measured sequence. At `live_pr.rs:117` the first PR call pins whatever base/head GitHub serves at that moment; at `:121` every warm sample repeats that live lookup. `PrContext::pin` reads the current PR before and after its own pagination, but its consistency check applies to one call, not across the benchmark samples (`pull_request.rs:324–354`). The report serializes only the first result's base/head (`live_pr.rs:143–144`). A force push or rebase between warm iterations yields one p50/p95 and API count over different PR trees; a later rerun of the exact documented command may measure a different PR tree even though `BCR_COMMIT` is unchanged. This is reachable for the live benchmark calls and violates AC-007's reproducible fixed-commit *warm* measurement and the R1 closure requirement for exact rerunnable commands. Siblings are all three capacity reports (`s20-wyrd-pr1.json`, `bench-vscode.json`, `bench-rust.json`) and their TASK-007 capacity rows; the VS Code and Rust reports use PRs independently of their fixed cold commits. The existing head-advance test checks only `ColdBuild::run_at`, so it cannot prove warm-sample identity.

**Testable correction:** keep production `PrContext::run` behavior and the verified cold path. In the opt-in capacity entrypoint, bind all first/warm PR samples to one declared base/head pair and fail the measurement if that pair changes; record the pair and require a PR state that can be rerun for the claimed fixed-commit benchmark. A fake-provider check should move the PR between warm samples and prove the benchmark refuses to aggregate unlike inputs. Refresh each affected report/row with the resulting proof. This corrects the benchmark owner without adding production persistence or changing the spec-named facades.
