## Proposed finding

### PROV-1 — Contract check reports failures as successful runs

- **Classification/gate:** `INCORRECT`, task contract (AC-006, REQ-017, TASK-007-R1 `FIND-TASK-007-2`). The new opt-in command is described as a contract *check* that exits nonzero on a failed case, but most named cases are observations only.
- **Root cause/defect class:** The command constructs result fields for provider compatibility but its terminal condition checks only whether any PR file lacks a patch. Its result shape permits a failed contract case with a successful process exit. The owner is `examples/provider_contract.rs`, not the production GitHub client.
- **Sibling sites:** `recursive_tree` records `truncated`/`invalid_paths` at lines 153–156 without rejecting an incomplete or invalid listing; `archive` records `gzip_magic` at lines 162–173 without requiring gzip; `conditional_observation` records the response status at lines 199–214 without requiring 304; `Recording::get` records rate headers at lines 63–75 but the command never requires them to be present. These are one missing-validation class. Repository, commit, blob, archive HTTP statuses and blob identity are already enforced by `GitHubClient`; PR patch omission is enforced at lines 225–227.
- **Reachable reproduction:** Run the command with an otherwise accessible controlled repository where the conditional replay returns 200 because its ETag changed, or a provider whose archive returns a 200 non-gzip body. The respective values become `status: 200` or `gzip_magic: false`; the command reaches `Ok(())` if PR #91 still has a missing patch. This follows directly from `run()`'s complete terminal branch at lines 216–228. A caller or CI invoking the opt-in lane would see exit 0 and may treat the captured run as an AC-006 pass. The checked-in run happens to have correct values, so it remains useful evidence of that particular observation.
- **Testable correction:** At the existing contract-command owner, fail when any required observed case has the wrong result, including conditional status, archive shape, complete valid recursive tree, and the documented API rate headers. Keep the real conditional probe outside the production client and the command outside normal CI. A focused no-network check of the report's pass/fail decision should prove one failing value makes the command nonzero; a rerun of the credentialed command should retain the successful captured proof.

**Verification limits.** I inspected immutable source and checked-in JSON. I did not rerun live GitHub access or Cargo; the orchestrator is running the required gate. The report alone cannot prove who controls `bohmian-ai/wyrd` or that the credential used was installation-scoped, although the command validates the supplied repository ID and SHA through the production client. The local fake tests establish response handling under scripted inputs, not a live 403/429 quota event.

**Overall: FAIL** on the contract-check false-pass path; the actual captured provider observations and production trust path passed this domain audit.
