## Material proposed findings

### BUDGET-1 — Verified entries accumulate for a whole compressed chunk

**Classification:** INCORRECT; REQ-013 memory bound and the task's bounded streamed ingest. **Root cause / defect class:** the push reader queues completed file buffers, while the caller drains that queue only after `GzDecoder::write_all` consumes the entire provider chunk. The owner shape permits an arbitrary number of verified files to coexist in `TarStream::verified`. **Siblings:** this is the single archive-to-index handoff; the fallback loop indexes one fetched blob at a time.

`TarStream::finish_entry` pushes each complete file into `verified` (archive.rs:218), and `consume_archive` does not call `ingest_verified` until after the whole compressed chunk is expanded (snapshot.rs:683–687). A small, highly compressible chunk can contain many eligible files; its expanded contents can approach the 4 GiB default expansion ceiling before the drain. Memory can then contain every queued source buffer alongside the symbolic index, despite the module's one-file-memory claim. The test fake itself returns the whole archive as one chunk (`testing.rs:18–36`), but the tests use tiny archives. **Correction:** drain or index each verified entry during decompression, or impose a separate bounded queue with explicit incomplete/fallback behavior. A proof should put many wanted files in one compressed chunk and check peak queued bytes/files, while retaining SHA verification and drop safety.

### BUDGET-2 — A provider blob ceiling is mistaken for verified oversize

**Classification:** INCORRECT; REQ-005 complete snapshot and INV-002/003 honest coverage. **Root cause / defect class:** `ResponseTooLarge` proves only that bytes exceed `RequestLimits::max_blob_bytes`; `Ingest::fallback` converts it unconditionally to benign `SkipReason::Oversize`, which means the snapshot may publish. The independent public `ColdBuildLimits::max_file_bytes` can be larger. **Siblings:** this is the only `ResponseTooLarge` mapping in cold fallback; `Ok(bytes) if bytes.len() > max_file_bytes` is a separate, verified path.

With an archive omission, a 512 KiB source file, `max_file_bytes = 1 MiB`, and `max_blob_bytes = 256 KiB`, `GitHubClient::blob` returns `ResponseTooLarge` before SHA verification (github.rs:1007–1013). Fallback marks that eligible file benign oversize (snapshot.rs:720–721), `Coverage::is_complete` accepts benign skips (snapshot.rs:126–127), and `ColdBuild::run` publishes. The file is within the build's eligibility bound and was never indexed or verified. **Correction:** distinguish a provider-bound failure from a proven file-bound excess; count the former as unindexed unless the known size or another validated fact proves it exceeds the effective file ceiling. A focused fake-provider case with unequal limits must leave the pointer unmoved and identify the path/blob in coverage.

### BUDGET-3 — Archive-bound exhaustion can publish a complete snapshot

**Classification:** INCORRECT against the task's explicit Scenario 2 and spec REQ-005. **Root cause / defect class:** archive errors are retained only as attempt stats; the publication decision consults file coverage after fallback and has no archive-bound state. **Siblings:** compressed provider bound and expanded tar bound flow through the same archive-error path; a fallback that fills all entries leads to publication in either case.

`consume_archive` records an expansion or provider error (snapshot.rs:681–693), then `ColdBuild::run` always attempts fallback and publishes when `coverage.is_complete()` (snapshot.rs:525–548). The checked-in `incomplete_attempts_report_coverage_and_keep_the_prior_pointer` test explicitly sets the expansion limit to 64, observes an archive-expansion error and six fallback blobs, then asserts `Published` (snapshot.rs:1305–1327). Scenario 2 says an exhausted archive bound leaves the pointer unmoved and returns incomplete coverage/reason; REQ-005 also says an exhausted archive bound yields incomplete scoped fallback. **Correction:** make archive-bound exhaustion part of the cold-build outcome before publication, retaining exact indexed/skipped coverage and the fallback reason. Focused proof should cover both compressed and expanded bounds with enough blob budget to recover every file, showing that recovery does not silently change the required outcome.
