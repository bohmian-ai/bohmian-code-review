## TASK-A-1 — Rejected root attributes file can produce false complete coverage

- **Classification / defect class:** INCORRECT; source-policy dependency is treated as an ordinary unsupported path. **Prior finding:** reopened `FIND-TASK-005-4` (`CLASS_INCOMPLETE`).
- **Root cause and owner shape:** `eligibility::classify` uses `path_exclusion` to call every rejected `.gitattributes` row a proven unsupported source, so `unknown` stays zero. That filename is also the source of the root generated/vendored policy. Its rejected identity prevents `root_attributes` from loading it, yet the empty default attributes are accepted as authoritative. The `RejectedPath` carries the canonical filename; the shared classification owner has enough information to preserve uncertainty about this policy input.
- **Siblings / reachable path:** `ColdBuild::start` and `Update::run` use `root_attributes` then `Ingest::new`; both can publish a complete snapshot/pointer. `PrContext::run` does the same for warm overlays, and its scoped branch can report the wrong nearby eligibility although scope stays partial. `Coverage::is_complete` and `ContextCoverage::is_full` then inherit the false classification. These are one root cause across cold, update, warm and scoped paths.
- **Violated obligation and evidence:** REQ-005's complete eligible-file snapshot, REQ-008's eligible scoped files, REQ-009's honest overlay, INV-002, and R2's rule that only a *proven* exclusion may be benign. `root_attributes` searches only validated `TreeEntry`s (`snapshot.rs:755–763`); `classify` marks a rejected canonical `.gitattributes` path `Unsupported` (`eligibility.rs:268–275,309–310`); `Ingest::finish` counts only `unknown` as `InvalidEntry` (`snapshot.rs:1013–1025`).
- **Observable consequence:** A head tree containing `vendor/keep.ts` and root `.gitattributes` with `vendor/keep.ts linguist-vendored=false` should index that supported source. If the listing supplies the canonical attributes path with an invalid SHA, the provider rejects that row. The candidate silently applies default attributes, excludes `vendor/keep.ts`, and can publish a supposedly complete snapshot or full PR overlay with missing facts. The rejected policy file's bytes need not be fetched to establish that full coverage is unproved.
- **Testable correction:** At the shared provider-to-eligibility boundary, treat a rejected root `.gitattributes` entry as unresolved eligibility policy, preventing complete snapshot and full overlay claims; retain scoped diagnostic and valid nearby context. A focused fake-provider journey with rejected root attributes and an override-dependent supported path must keep cold/update pointers unchanged, mark warm overlay incomplete, and retain scoped partial coverage. Preserve R2's benign handling for rejected ordinary unsupported paths such as `README.md`.
