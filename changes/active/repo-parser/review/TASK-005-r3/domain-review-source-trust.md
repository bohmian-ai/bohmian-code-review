## DOMAIN-TRUST-1 — Rejected root attributes are misclassified as harmless

- **Classification:** INCORRECT; prior `FIND-TASK-005-4` is class-incomplete. **Defect class and owner shape:** shared rejected-entry classification treats every canonical path with an unsupported language as independently ineligible. It has no exception for `.gitattributes`, whose unverified content determines the eligibility of *other* paths. This is a missing dependency at the `eligibility::classify` boundary, enabled by `path_exclusion` applying the language check before considering policy-file role.
- **Violated obligation:** The spec's eligible-file definition includes root `.gitattributes` generated/vendored overrides; REQ-005/006 and INV-002/003 permit a complete published snapshot only when eligibility and all resulting facts are validated. REQ-009 requires honest overlay coverage. R2 FIND-4 permits a benign rejection only where trusted facts prove ineligibility.
- **Evidence and reachable path:** `GitHubClient::tree` rejects an entry with canonical path `.gitattributes` and malformed SHA or unknown mode into `listing.rejected`. `root_attributes` searches only accepted `listing.entries`, so it returns defaults. `classify` then passes the rejected `.gitattributes` through `path_exclusion`; the language query returns unsupported and records a benign `Unsupported` exclusion, leaving `unknown == 0`. Other accepted source paths are classified with default attributes. If the root file would have marked `generated/a.ts` generated, the candidate instead indexes it and can publish the tree as complete. This is reachable from `ColdBuild::start` and `Update::run`; the same `root_attributes`/`Ingest::new` chain in repository-scope `PrContext::run` can claim a complete overlay and full PR-head coverage. In scoped mode the result remains scoped, but its file eligibility still uses unverified defaults. These are sibling effects of the one classifier decision.
- **Observable consequence:** a pointer can target a snapshot that claims complete coverage under an unverified eligibility policy; a warm PR may publish selected source from a path the actual root rules exclude, while reporting full coverage. Retrying the same tree preserves the false classification.
- **Testable correction:** At the shared provider-to-eligibility boundary, treat a rejected root `.gitattributes` whose mode/content cannot be trusted as unknown policy input, even though its path is not a source language. Preserve benign classification for ordinary proven-ineligible rejected paths and the valid verified-attributes path. A focused fake-provider case with a rejected root `.gitattributes` and a valid source path should keep cold publication and update pointer advancement blocked, and make warm overlay coverage incomplete; a valid root attributes blob and rejected ordinary `README.md` should retain complete outcomes.
