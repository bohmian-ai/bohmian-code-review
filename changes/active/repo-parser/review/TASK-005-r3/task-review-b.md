## Proposed findings

### TASK-B-1 — INCORRECT; rejected eligibility-policy input is treated as an ordinary unsupported path

**Root cause and defect class.** The shared rejection classifier decides that every canonical unsupported path is a benign exclusion (`eligibility.rs:268–275`), including the root `.gitattributes` file. That file is an input to eligibility policy: `root_attributes` reads only validated tree entries and silently uses empty defaults if its entry was rejected (`snapshot.rs:750–763`). The owner shape is the same untyped `RejectedPath` path classification for ordinary source candidates and policy inputs. The earlier FIND-TASK-005-4 correction is incomplete for this sibling.

**Reachability and consequence.** A tree can contain a rejected `.gitattributes` entry with canonical path and invalid SHA plus a valid `vendor/a.ts` entry. The actual attributes may contain `vendor/a.ts -linguist-vendored`, which makes that source eligible under the approved root-override rule. Since the rejected policy file is absent from `listing.entries`, `root_attributes` returns defaults; `path_exclusion` marks `vendor/a.ts` as `VendoredSegment`, and marks rejected `.gitattributes` as `Unsupported`. `Coverage::unindexed` is zero, so cold build can publish a complete snapshot omitting an eligible file (`snapshot.rs:656–677`). The same `root_attributes`/`Ingest` path is used by incremental update and by warm/scoped PR context (`pull_request.rs:162–190`), so their eligibility and completeness claims are sibling effects. This violates spec terms at lines 31–35, REQ-005/006/009 and INV-002, and R2's rule that only trusted facts proving ineligibility may be benign. An invalid policy blob need not be parsed; it must prevent a full-coverage claim where its unknown rules could change eligibility.

**Testable correction.** At the shared tree/attribute classification boundary, treat a rejected root `.gitattributes` as unknown policy input before declaring complete coverage; retain the valid-file work and partial/scoped context. Cover cold publication, update pointer, warm overlay, and scoped diagnostics with a rejected `.gitattributes` and a source whose eligibility can be changed by an override. Preserve benign treatment of ordinary unsupported `README.md` and strict Git identity validation.

### TASK-B-2 — INCORRECT; changed-head ingestion bypasses the scoped file and request limit

**Root cause and defect class.** `PrContext::run` takes every accepted PR file through `changed_head` before it computes the scoped fallback allowance (`pull_request.rs:211–224`). `changed_head` fetches and ingests an eligible pending path without consulting `max_scoped_files` (`pull_request.rs:401–410`). The limit controls only later `Ingest::fallback`; it is not a bound on the shared scoped ingest workflow. No owner shape change is required, but the bound must govern both entry points into that workflow.

**Reachability and consequence.** With no snapshot and `max_scoped_files=1`, two accepted changed `.ts` files in nearby directories, each with a valid nonempty patch, both appear in the scoped `Ingest::new` set. `changed_head` fetches and indexes both, producing `coverage.files.indexed=2`; `saturating_sub` then gives fallback zero. With up to the PR-file ceiling, indexed files can exceed the configured scoped ceiling. This violates REQ-008's fixed file bound and the `PrContextLimits::max_scoped_files` contract at lines 47–48. The same bypass applies to every changed path in a scoped run; warm overlay has a different bound and is not this finding. The existing focused scoped test uses one changed head, so its pass does not cover this case.

**Testable correction.** Enforce the eligible scoped-index file ceiling across changed-head ingestion and fallback while preserving the separate obligation to analyze every valid PR file and to exclude every changed path from secondary candidates. Prove with two valid changed heads and a limit of one that at most one enters the scoped index, the other can still contribute changed-line names, and coverage names the unindexed path. Do not charge a mandatory changed-head analysis fetch against a limit meant for extra scoped-index fetches.
