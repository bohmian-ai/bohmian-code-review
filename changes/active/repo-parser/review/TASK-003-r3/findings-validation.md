### FIND-TASK-003-2 — CLASS_INCOMPLETE

- **Wave 1 sources:** `TASK-B-1`, `DOM-TRUST-R3-1` (one root cause). **Gate:** task contract, [spec REQ-005, REQ-006, REQ-013](../../spec.md), original TASK-003 Scenarios 2–3, and prior FIND-2. **Classification:** `INCORRECT`. **Defect class:** execution is checked during ingest but not carried across the snapshot publication and reuse IO boundaries. The candidate-owned `ColdBuild::publish` shape has no `Execution` parameter, so it cannot observe interruption.
- **Root cause and siblings:** `ColdBuild::run` last checks at `snapshot.rs:525`, then serializes at `543-551` and calls `publish` at `552`. `publish` records the key at `582`, creates/adopts the object at `583`, reads it back at `587`, and advances the pointer at `600-602` without another check. The matching-pointer reuse path reads storage and returns `Reused` at `466-472` without checking again. These are one missing execution boundary, not separate findings. `Ingest::consume_archive` now checks compressed and expanded reads (`snapshot.rs:695-721`); the R2 archive-read sibling itself is closed.
- **Independent reproduction:** Public `ColdBuild::run` → complete `Ingest::finish` → successful `execution.check()` at `525` → `ColdBuild::publish`. A caller-supplied `ObjectStorage::read` may cancel the shared token while returning the validated object. `publish` then calls `SnapshotStore::publish_snapshot_pointer` and `run` returns `Published` although the token was cancelled before pointer advancement. On an existing matching pointer, cancellation during `Snapshots::read` likewise returns `Reused`. Both storage hooks are legal injected implementations; `Execution::check` observes the token (`execution.rs:72-80`). This is a deterministic source-path reproduction, not a claim that an IO operation already in progress can be preempted.
- **Consequence:** An interrupted cold build can advance its pointer or report successful reuse rather than report interruption. The prior pointer and retry/fallback contract is lost. R1's final check and R2's interruptible archive reader cover ingest, but their shape leaves publication outside execution; this reopens the earlier FIND-2 design rather than assigning a new ID.
- **Smallest safe correction:** Reuse `Execution::check` at the existing `ColdBuild` owner. Carry `Execution` through publication, observe interruption after read-back and immediately before conditional pointer publication, and translate an observed interruption to the existing `IncompleteReason::Interrupted` outcome with the already computed coverage and ingest stats. Check the reused-object path after its read and before returning `Reused`. Preserve record-before-write, object identity and byte validation, CAS conflict behavior, and collectability. No new trait, backend, timer, or spec-named API is needed. A cancellation racing *inside* the atomic pointer-store call has the store's linearization semantics; do not promise to undo an already committed CAS.
- **Focused closure proof:** An injected storage read that cancels before returning valid bytes must yield `Incomplete(Interrupted(Cancelled))`, leave the prior pointer intact, and retain a collectable record for the object; repeat for adoption/read-back and for a matching-pointer reuse read. A check at the final pre-CAS boundary must also report an already-expired deadline without moving the pointer. Existing publication, isolation, and archive cancellation tests must continue to pass.

### FIND-TASK-003-7 — CONFIRMED

- **Wave 1 source:** `DOM-TRUST-R3-2`. **Gate:** task contract, [spec REQ-005](../../spec.md) and the [approved plan's eligibility rule](../../symbolic-context-service-plan.md). **Classification:** `INCORRECT`. **Defect class:** Git attribute reset is collapsed into explicit false before eligibility is decided. The `AttributeRule` representation cannot distinguish `!attr` (unspecified) from `-attr` (false).
- **Root cause and siblings:** `parse_attribute` maps both prefixes to `false` at `eligibility.rs:136-144`; `RootAttributes::parse` records that value at `108-115`; `resolve` propagates it at `123-132`. `exclusion` then bypasses the built-in vendored-segment rule when `vendored == Some(false)` at `279`, and the built-in minified-output rule when `generated == Some(false)` at `282`. Both reset forms are sibling effects of the same representation error.
- **Independent reproduction:** In a temporary repository, `.gitattributes` containing `vendor/** linguist-vendored` and `vendor/a.ts !linguist-vendored` produces `git check-attr linguist-vendored -- vendor/a.ts vendor/b.ts` output `vendor/a.ts: linguist-vendored: unspecified` and `vendor/b.ts: linguist-vendored: set`. Candidate `parse_attribute("!linguist-vendored")` instead returns `false`; `resolve("vendor/a.ts")` becomes `Some(false)` and `exclusion` admits the supported `vendor/a.ts` despite its built-in excluded segment. The same trace admits `src/a.min.js` under `!linguist-generated`. `ColdBuild::run` reaches this through its root `.gitattributes` blob and `Ingest::new` (`snapshot.rs:493-507,650-657`).
- **Consequence:** Files excluded by the task's vendored/generated eligibility policy can be fetched and indexed; coverage can report them eligible and a complete snapshot can be published with unwanted facts.
- **Smallest safe correction:** At `RootAttributes` parsing/resolution, represent “no rule on this line,” Git's explicit false, and Git's reset-to-unspecified separately, preserving last matching rule behavior. Feed the resolved unspecified state to the existing `exclusion` checks so built-in segment/minified rules apply. Keep `-attr` and `attr=false` as explicit overrides. This is candidate-owned internal state; no spec revision or new dependency is required.
- **Focused closure proof:** A small owner test should prove `!linguist-vendored` after a previous set resolves to unspecified and excludes `vendor/a.ts`; `!linguist-generated` excludes `src/a.min.js`; `-attr`/`attr=false` still admit the corresponding built-in path; ordinary set and last-match behavior remain. The existing cold-build owner lane then checks composition.
