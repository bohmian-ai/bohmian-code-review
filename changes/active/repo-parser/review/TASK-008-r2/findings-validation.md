### FIND-008-2 — no-declaration files are published as indexed

- **Wave 1 source:** `SNAPSHOT-008-R2-1`. **Status:** REVISED (the observed discrepancy is confirmed; the correction is at the declaration projection, not a new raw-node guard). **Classification:** INCORRECT. **Gate:** approved Complete snapshot term (`spec.md:33`), REQ-001 (`:55`), revision 14 (`:149`), and TASK-008 Scenario 3 (`tasks/TASK-008-recovered-tree-extraction.md:52-64`).
- **Root cause / defect class:** `Ingest::ingest` uses the extractor's raw node list to decide whether a file has indexable facts (`snapshot.rs:1005-1015`). That list may contain import, export, or parameter nodes although `SymbolIndex::export` discards those kinds from the persisted declaration projection (`index/src/lib.rs:123-140,186-194`). The pipeline can therefore represent `Indexed` for a path whose published `IndexedFileFacts.declarations` is empty. This is a mismatched outcome shape at the facade/pipeline seam.
- **Siblings and caller/producer closure:** `SymbolicContext::upsert` extracts and passes nodes into the index, then returns the unfiltered nodes (`bohmian-code-review/src/lib.rs:148-157`); `SymbolIndex::upsert` posts only declarations (`index/src/lib.rs:59-82`), and `export` retains only declarations (`:127-140`). The TypeScript import producer emits `NodeKind::Import` (`extract/tsjs/mod.rs:881`, `extract/tsjs/extractors.rs:1120-1145`). The shared `Ingest::ingest` is reached from archive verification (`snapshot.rs:900-905`), verified blob fallback (`:966-985`), and PR head overlay (`pull_request.rs:432`). `Ingest::reuse` loads prior empty declaration records and increments `indexed` (`snapshot.rs:944-952`), so a later update carries the same mismatch. `ColdBuild::complete` publishes `context.export()` with the misleading coverage (`snapshot.rs:648-692`). These are one root cause, not separate findings.
- **Independent reproduction:** A read-only external probe at `/tmp/bcr-r2-probe` invoked public `SymbolicContext::upsert("src/only.ts", b"import { X } from './x';")` against the candidate, then `export()`. It printed nodes `[(File, "only.ts"), (Import, "./x")]` and export `[("src/only.ts", [])]` (declarations empty). Source trace through `snapshot.rs:1006` takes the `Ok(_)` indexed branch for those nodes; `:1013-1014` increments indexed with no `NoFacts` skip. The same branch is shared by all three callers above. This is realistic verified source; no provider failure is involved.
- **Observable consequence:** A complete published snapshot reports that this eligible file was indexed, while its durable declaration projection has no symbol facts and its coverage omits the required content-skip reason and blob identity. Reuse preserves that false count. This does not corrupt another file or create a false posting, but it violates the task's explicit no-facts coverage contract.
- **Decision-complete root-cause correction:** Make the facade/index's **persistable declaration projection** the only shape accepted as an indexed ingest outcome: a closed `NoFacts` outcome or an `Indexed` outcome carrying a nonempty declaration projection. Reuse the existing `IndexedFileFacts`/`DeclarationFact` projection and `SymbolIndex::is_declaration` ownership; the pipeline must not inspect raw `NodeKind` to rediscover which nodes survive export. The `NoFacts` path records the verified path/blob and leaves no context entry. Apply the same classification to unchanged prior records with empty declarations during `Ingest::reuse`, so pre-correction snapshots under the same extraction version converge on update. Preserve file-local extraction errors as blocking skips, the existing LFS/oversize classification, source-free snapshot serialization, and PR head admission/verification. Remove the pipeline's otherwise unnecessary `NodeKind` import/re-export if no remaining caller uses it. This reshapes the candidate-owned no-facts seam; it needs no new product or spec-named API decision.
- **Focused closure proof:** One fake-provider cold-build case with a valid import-only TypeScript file and one normal declaration file must publish with `NoFacts` carrying the import file's blob, indexed count one, and no empty-declaration fact record. Exercise the shared update/reuse path with a prior source-free empty-declaration fact record; verify it becomes the same skip. A PR head overlay using the import-only file must report the same classification without changing head verification. Keep the existing malformed no-declaration, fetch-failure, and normal-declaration cases; run `mise run test:pipeline`, `test:symbolic-context:journey`, `fmt:check`, and `lints`.
