## Finding SNAPSHOT-008-R2-1 — non-declaration nodes make a no-facts file appear indexed

- **Classification / obligation:** INCORRECT; TASK-008 scenario 3 and acceptance criterion 3, plus the spec's Complete snapshot and Coverage terms, require a verified eligible file with no extractable snapshot facts to be a blob-identified `NoFacts` skip, not an indexed file.
- **Root cause and defect class:** `Ingest::ingest` defines no-facts as “all nodes are `File`.” That tests raw extractor node shape instead of whether the snapshot has a declaration fact. The snapshot export deliberately drops `Import`, `Export`, and `Parameter` nodes. This is a mismatched classification boundary in the shared ingest owner; its shape permits the defect.
- **Direct traced reproduction:** An eligible `src/only.ts` containing `import { User } from './user';` reaches the TypeScript `import_statement` branch, which calls `extract_import` and creates an `"import"` node. `SymbolicContext::upsert` returns those nodes. Because `Import != File`, the new `NoFacts` arm does not run: `Ingest::ingest` increments `indexed` and records no skip. `SymbolIndex::export` filters the import node out, so the published `IndexedFileFacts` for `src/only.ts` has an empty `declarations` list. `Coverage::is_complete` accepts the attempt and cold build publishes it. An unchanged update loads that empty fact and counts it indexed again. A PR head containing the same source is also counted indexed by `changed_head` or overlay fallback. This is an ordinary valid file, with no fetch or parse failure.
- **Sibling sweep:** There is one faulty classifier, at `snapshot.rs:1006`; its sinks are `snapshot.rs:905` (verified archive), `snapshot.rs:981` (verified blob fallback used by cold build/update/overlay), and `pull_request.rs:432` (changed PR head). `Ingest::reuse` at `snapshot.rs:944–955` carries the wrong persisted status into later updates and overlays. The same class covers export-only and parameter-only extracted node sets where no declaration is retained. No separate classifier was found in update or overlay.
- **Consequence:** `coverage.indexed` overstates files with usable declaration facts, `coverage.skipped` omits their blob identities and content reason, and published/read-back snapshot coverage repeats the false status. Selection currently gains no postings from such files; the contract failure is the externally visible coverage and skip identity.
- **Testable correction:** Make the shared ingest outcome reflect the declaration facts that the snapshot retains, so any successfully extracted file with none is recorded once as `NoFacts` with its blob, while files with declarations remain indexed. Exercise a valid import-only file through cold build and through reuse/update or PR overlay, asserting the skip, counts, complete publication, and no stale postings. Preserve fetch, verification, and extractor failures as non-benign outcomes. This replaces the mismatched classification rule at its owner; it needs no added downstream guards.
