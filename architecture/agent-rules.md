# Agent rules

- Follow `AGENTS.md` and `bohmian-code-review-design.md` before editing. Preserve the six crate owners and their one-way dependency graph.
- A task that changes the reviewer's output must include or update the real public two-pass journey. Unit tests cannot replace a missing journey.
- Tests are inline with an owning Rust module by default. An external test earns its place by crossing crate boundaries through the public facade. Keep the fast lane credential-free and network-free.
- Use exact pinned grammar dependencies and vendored grammar provenance. Build scripts write generated output only to `OUT_DIR`.
- Validate effective input values: canonical paths, nonempty changed-line ranges, and supplied token counts. Do not turn an omitted file or budget failure into apparent success.
- A malformed or unsupported file must not corrupt another file's in-memory index entries. Replacement either exposes the new complete facts or preserves the old complete facts on failure.
- Do not retain source blobs in the index, fetch source in a library crate, or copy the donor's PostgreSQL, SDK, or `SourceTree` orchestration. A no-clone service may use these crates without local Git metadata.
- Use concrete owners and inherent methods for stateful workflows. Avoid zero-sized utility structs, one-implementation traits, and speculative abstraction layers. Pure deterministic helpers may remain free functions.
- Keep imports at module top; use bare imported types in signatures. New/materially changed Rust items require meaningful rustdoc, `# Errors` for fallible operations, and `# Panics` where relevant.
- Never hide a failing check with `#[allow]`, `#[ignore]`, a weakened assertion, a changed golden, or a broadened skip. Fix the defect or report the exact blocker.
- Skills under `.agents/skills` are canonical. `.claude/skills` is generated by `scripts/sync-agent-skills.sh`; never edit the mirror directly.
- A task review checks an immutable cumulative candidate against the approved spec and actual diff. A change review checks cross-task seams and the public journey. Neither substitutes a plausible summary for observable evidence.
- Use locally configured Git identity. Never alter it, impersonate another contributor, or add AI co-author trailers. Do not push or publish without user authorization.
